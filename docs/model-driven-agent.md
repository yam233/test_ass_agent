# 模型驱动 Agent：运行、边界与验收

当前正式模型路径采用 NativeModel 协议 v2：模型逐轮提出目标、工具调用、澄清及完成结论；WorkflowRuntime 校验并执行。业务平台仍为本地 SQLite mock。无需 LangGraph、向量数据库或多 Agent。

## 两种模式

- `LLM_MODE=remote`：真实模型理解用户目标、自然语言补充和更正，依观察决定下一步；API 不可用时明确失败。
- `LLM_MODE=offline`：RuleModel 的有限规则演示/工程回归，不代表模型理解能力，不静默接管 remote 故障。

保持 API Key 在本地忽略文件 `config/local/agent_secrets.json` 或环境变量中。原有 `/workflows` 请求格式、SDK、审批和队列继续使用。远程模型工作于 mock 环境，真实模型与真实业务平台是两个独立维度。

```bash
LLM_MODE=remote python -m uvicorn api.offline_server:app --host 127.0.0.1 --port 8000
```

## 模型如何工作

保留十个业务工具，另有三个模型控制函数，不属于平台写权限：

- `update_task`：模型记录目标及来源（u0 原请求，u1 第一次补充等），支持查询、明确写入、条件配置、关联核验、不支持。这个结构是可修订的任务理解，不是固定前置执行计划。
- `recall_memory`：模型按需读取同操作人、同会话、同环境历史。分页有上限，历史只供指代和事实追溯，不证明当前状态。
- `finish_task`：模型逐项目标提交结论与工具观察 seq，运行时验证具体证据。

模型可先追问、查询或发现工具；执行前需有当前用户版本的任务理解。写操作必须符合目标参数并经过原有服务端权限校验、动作审批。模型不能批准自己的动作，也不能从历史记忆恢复授权。

例：用户要求“如果 gift_multiplier 不是2就改成2并确认”。模型先查询；已经为2时以查询证据说明无需修改，否则提出写入审批，执行后重新查询。Runtime 不编码该句请求的工具顺序。

## 补参和更正

`/workflows/{task_id}/resume` 的 `reply` 接收自然语言，例如“10个，用户改成456”。协议 v2 下由模型重新解释，不用用户把多个字段整理成 JSON。

待审批时同样可提交 `reply`：旧动作在同一事务内取消，补充信息持久化，模型重新理解并生成新动作。旧 action_id 不能审批新参数。`reply` 与 `decision` 不能同时提交。运行中或已经提交的动作不能通过更正改写；完成任务后可新建同会话任务处理后续要求。

旧协议任务/离线规则保留原补参行为；不要混用模型模式恢复同一活动任务。

## 上下文与记忆

- 按时间顺序排列用户补充与工具调用，避免把后来更正误解为先前指令。
- 每轮包含任务理解、用户来源、近期观察、最近成功写入和有限历史事实。
- 超限时将较老观察变成带 seq、工具、参数、关键结果的提取式摘要；大结果保留 ref_id 按需读取。
- 提取式摘要不增加模型调用，不生成新的事实；必要用户约束仍超过预算时明确停止。
- 任务状态、原始对话和证据持久化。另以 SQLite 索引保存最近已结束任务的摘要，自动提供最近3条；可分页读取最近7天、最多105条范围内的记录。
- 摘要中保留全部已提交写入事实（包括部分成功及实际数量）和最近8条成功读取观察；原任务完整审计仍保留。旧任务结果引用不能跨任务直接读取，需重新查询对应批次。
- 7天是检索窗口，不是自动删除承诺。跨会话画像、长期偏好学习、语义向量检索不在本次范围。

## 证据化完成与回复

正式模型路径不再用原始请求关键词作为完成判定。模型逐项选择证据，代码校验：

- 写入：本任务、本作用域的真实成功回执，参数匹配，实际数量满足本次操作。
- 查询：与目标参数相符的成功查询。
- 条件配置：查询值符合目标；不能用修改前的旧读值证明修改后的状态。
- 核验：对应写目标的批次或配置版本，以及操作后的查询。
- 未完成/不支持：明确列出，不能包装为整项成功。

模型组织答复使用 `{{目标id}}` 事实占位符；服务端填充经校验的中文事实句。任意自由陈述、未知占位符或遗漏目标会回退事实摘要。这里有意限制自由措辞，不能宣称已经支持不受约束的模型文案生成。返回 `answer_fallback` 可观察回退。

目标结构本身由模型理解，代码不能证明模型没有误解或漏提用户意图。因此 `completion_scope=validated_model_goals` 不等于通用语义正确；后者依赖独立场景判分。权限仍由服务端和用户审批控制。

## 评测

新增12类、24个变体：条件分支、改写表达、缺参、更正、写后核验、会话记忆、会话隔离、非法参数、不支持操作、工具输出注入、重启补参、临时故障。长上下文压缩另外有确定性工程测试。

评测器只把用户消息交给模型，不提供标准工具序列。读取 SQLite、回执及具体查询范围判分；审批代理只批准场景预期动作，拒绝次数单独报告，不能把“被审批代理拦住”算成模型决策正确。

```bash
# 工程测试，不调用真实模型
python -m pytest tests tests_legacy -q

# 会产生 API 调用费用，必须显式指定总预算和新录制文件
python -m scripts.evaluate_agent --mode remote --token-budget 120000 \
  --recording reports/agent-decisions.jsonl --output reports/agent-evaluation.json

# 不调用 API：观察、工具协议和输出预算必须匹配录制
python -m scripts.evaluate_agent --mode replay \
  --recording reports/agent-decisions.jsonl --output reports/agent-replay.json
```

预算不足的场景标记 skipped；报告区分已执行通过率和覆盖率。未返回的货币费用保留 null，不根据 Token 猜价格。录制仅含合成输入/输出，不包含密钥。

实际本次验收与未覆盖项见 [改造验收记录](model-driven-acceptance.md)。24条用例已定义，并不意味着都进行了付费模型验收。
