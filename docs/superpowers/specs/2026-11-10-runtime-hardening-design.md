# TestOps Agent 整合改造方案

日期：2026-11-10。状态：用户授权后已按五批实施；下文保留原设计依据。验收与实际边界见 [验收记录](../../runtime-hardening-acceptance.md)。

## 目标和边界

保留原有审批、事务回执、幂等和 checkpoint 内核，将本地合成测试助手完善为可复核、可恢复、可调度的单机运行时。全程保持平台 mock；模型接口可替换。当前不是生产多租户平台。

本轮包含两份外部评审的有效问题；不以“13 项能力”“工具超过 15 个”等经验数字作为强制架构标准。不因缺少规划节点、并行工具或跨任务记忆就判定单 agent 内核不完整。

## 证据

核验基于发布副本 commit 195e63a；原工作区 workflow.py 与该副本相同。全部复现使用临时 SQLite 和脚本模型，无付费模型调用。

| 项目 | 复核结果 |
|---|---|
| read_ref 大页 | 60 行经运行时读取后只剩 sample_3，引用数量 1→2；外部化阈值实际按字符计数 |
| 新环境 | requirements-offline 安装完成后，默认测试收集缺 aiohttp；旧测试还直接依赖 pymysql。排除旧架构测试后 82 通过、2 失败 |
| 子进程路径 | 依赖齐全、无源码内 .venv 的副本：116 通过、2 失败；两处硬编码解释器路径 |
| 缺省写入上下文 | 空 context 变为 local/default/uat；写前仍等待审批，批准后才写入 |
| dry_run | start(dry_run=True) 创建可批准动作；resume 不携带 dry_run 并批准后实际写入 |
| allowed_tools | 传入只允许 query_data，seed 被拒绝且未创建动作；不是完全无效，缺可信配置来源与跨续跑约束 |
| 同步超时 | max_seconds=0.02，注入同步 sleep(0.25)，实际约 0.288 秒才返回 timeout |
| 评测 | fixture 测运行时；真实模型记录已有但样本小、含补测复用；不能合成总体模型成功率 |
| 审批、版本 | 动作表已有 approved_at/operator；缺完整事件历史。prompt_ver 固定，checkpoint 无 schema_version |

## 方案取舍

1. 只修缺陷：成本最低，但调度、生命周期和统一评测仍分散。
2. **推荐：分批加固现有内核，加单机持久调度与评测入口。** 每批单独验收，保留兼容入口，先离线验证后做小批远程验收。
3. 全面平台化：引入分布式队列、租户认证、多 agent 和外部平台适配。当前缺少可验证需求，不列入本轮。

## 第一批：可复现性和契约修复（阻断发布）

- 分离 core、兼容入口、旧架构测试依赖。先拆开导入耦合，再减依赖；核心 workflow 不能因导入 langgraph_agent 包而加载图运行时。旧架构测试独立目录和命令，不静默丢弃覆盖。默认 pytest 跑核心测试，CI 另跑完整测试配置。
- 子进程统一 sys.executable；在仓库外创建虚拟环境并执行验证，杜绝只测固定 .venv 的假可移植性。
- read_ref 返回实际行，不再次生成引用；最多 100 行且每页最多 16 KiB UTF-8 序列化响应。返回 returned_count/next_offset/truncated；单行超限明确 ROW_TOO_LARGE，不能返回空页伪装成功。普通 100 行合计不超限时必须完整返回。
- 任务持久化 mode=execute|dry_run，创建后不可改变。dry_run 允许查询，在第一个写意图处返回预览并终止为 planned；不创建 actions、preconditions 或 receipts，不执行后续依赖写结果的步骤。可保留任务及追踪记录，不能假称整条链路已演练完毕。
- 预演转正式执行必须新建任务并重新审批；resume 即使省略或篡改 dry_run 也不能升级原任务。
- 引入 schema_version=1 的最小加载迁移，以支撑 mode 等新增字段。历史无版本任务按 execute 迁移，未知新版本拒绝继续；不声称能恢复历史未保存的 dry_run 意图。

验收：新环境核心/完整测试两套入口均通过；100 行读取不增殖引用；预演及其续跑无业务写入、无可执行审批动作；既有进程崩溃与并发幂等测试保持通过。

## 第二批：策略、审计和模型调用可靠性

- 写操作必须显式 operator/env；去掉 API 提前注入的写权限默认值。读任务仍允许本地默认上下文，但不能用该默认上下文获得写权限。旧入口示例同步更新。
- 服务端 policy.json 提供已知本地身份的工具范围、风险规则和影响量上限。客户端 allowed_tools 只能进一步收窄，不能扩大；创建时保存限制，续跑不能移除。有效权限为创建时授权、当前服务端授权、任务限制三者交集；权限撤销在准备、审批和执行时均生效。
- 创建时绑定 operator/session_id/env，之后不可更改；审批、取消、读取和续跑必须使用相同 scope，不能以新 context 重新解释任务归属。本轮审批者与创建者相同，不引入跨身份代批；改环境或身份必须新建任务。
- operator 仍是本地身份声明，不等于认证。生产禁写保留为不可被普通配置放开的全局约束。跨用户部署需要另行设计可信身份入口。
- write_destr 增加结构化删除意图确认，绑定 action_id、批次、参数及影响快照；默认单批最多 1000 个礼物，超过阈值拒绝。执行前重查影响量和版本，变化后旧审批失效。复用现有有时效的动作审批，不另堆一套同义 token。
- 增加追加式 audit 事件：prepare/approve/deny/expire/start/receipt/reconcile/cancel。审批事件与动作状态同事务；平台提交事件与回执同事务，支持崩溃后去重补齐任务关联。记录 actor/scope/task/action/args_hash/policy_version/时间，不记录密钥。
- 工具契约、提示词、模型关键参数均有指纹；有效配置快照以脱敏 artifact 保存，哈希只是标识，不代替原文。
- 模型 429/可重试 5xx/连接超时最多重试 2 次，退避 1、3 秒，遵守剩余总时间与 token 预算；鉴权和 schema 错误不盲目重试。记录每次尝试，未返回 usage 的尝试保留预算占用。
- 输出上限可配置，建议默认 1024；finish_reason=length 最多额外重试 1 次，输出上限不超过 2048 且受剩余预算约束。总模型尝试仍受 max_steps 硬限；不据旧报告断言 512 必然造成初次失败。

验收：去掉限制、冒用动作、策略撤销、过期审批均不能写；预演不能升级；完整审计链可导出；暂态模型失败恢复而预算不超支。

## 第三批：状态生命周期与上下文治理

- checkpoint 明确 version/revision/mode/status/stop_reason/pending/budget；迁移纯函数、可重复执行，旧数据备份后按事务升级。未知版本明确失败。
- 扩充 planned/cancelled/expired/reconciliation_required 等必要状态，限定允许迁移；不得将提交结果不明直接标成“取消且未执行”。
- refs 增加 created_at 与 task_id 索引。默认仅清理终态任务保留 7 天后的 refs；活动和待批任务引用保留。清理 refs 不删除动作、回执和审计。
- 待批任务按已有动作 expires_at（目前 5 分钟）过期；启动时、显式维护命令和后续调度器周期性清扫。过期与审批并发用事务裁决，不能让已批准动作被旧清扫结果覆盖。
- reset 增加 --dry-run 显示影响范围；实际 reset 只能在无执行者的独占维护状态下进行。尚未完成对账的动作不允许自动 GC。
- 抽出上下文构造器：记录 system/tools/task/recent_tools/summary_refs 五区字节数。默认模型输入硬限 32 KiB；同时受现有总 token 预算约束，字节上界不冒充精确 tokenizer。
- 保留工具契约、用户目标、最新澄清与当前动作证据；按完整 assistant/tool 消息对压缩旧观察，摘要作为标记数据处理，不能升级为额外 system 指令。若必要内容已超限，明确停止，不悄悄删任务约束。
- 200 条历史用于构造器测试；运行时仍遵守 max_steps<=100，使用 10–20 步任务测试预算与末步核验。不为压测放开生产预算。

验收：旧 checkpoint 可迁移；过期竞态有确定结果；GC 不伤活动引用和回执；上下文有分区统计、消息配对完整，超限行为可解释。

## 第四批：统一评测与可观测出口

- 新增统一 runner，复用旧 oracle；不把三个脚本全部重写。Environment 管隔离场景、快照和不变量，真实正确性继续来自 SQLite 状态及回执。
- 四类报告分开：确定性运行时回归、固定随机种子的错误决策测试、历史轨迹回放、实时模型评测。禁止把其中一类的分数当成另一类。
- 独立 expected_tool/expected_args/expected_stop_reason 与最终状态断言，不从 fixture 的答案推导正确答案。
- 增加读工具故障注入，覆盖 wrong tool/漏参/重复调用/越权/写后重复写/预算耗尽；分别统计决策错误、拦截率、错误放行率和正常任务误拒率，不能靠全部拒绝获得高分。
- 至少 6 条 3–5 工具步骤的业务链，含写后核验、配置漂移、回滚冲突、清理及拒批分支。另保留长历史与 10–20 步构造场景。
- 区分执行尝试数、同 action 实际提交数、新 action 再审批；不否定数据库唯一约束作为幂等保障的价值。
- record/replay 保存模型、有效提示词/契约指纹、配置、usage、finish_reason、动作与观察；动态 batch/ref/action ID 用符号映射。观察不匹配时标记 replay_incompatible，不能继续冒充真实交互。
- 基线可比性校验覆盖 case_set、oracle、环境契约、评测口径版本；模型/prompt 变化为比较维度，不混为相同实验。
- 实时模型验收先选固定 12 条选择题和 6 条链路，默认不运行；显式 remote 开关和总 token 上限才启用。重复试验单独记录，不用复用的成功样本充当独立重复；金额未知保留 null。
- trace/audit 提供按 scope 的 JSONL 导出和离线聚合。当前不建设仪表盘；其他 agent_eval_harness 仓库未核验，先留适配接口，不承诺本轮跨仓集成。

验收：一条 CLI 可选 suite/model/repeat 并产出 JSONL、汇总与可比基线差异；fixture、回放和远程结果有明确标签；新环境实现能复用 runner。

## 第五批：单机持久调度、超时与取消

- 保留同步 /workflows 的等待响应行为，增加 dispatch=queued（默认 inline）。两种 HTTP 模式均走同一个持久 job 队列、任务锁和执行池：inline 等待本段执行到终态/待批/待澄清后返回，queued 先返回 202/task_id。任务与 job 事务创建；resume 批准与可运行 job 创建同事务。内存队列只作通知。
- 默认 1 个调度器、2 个执行进程、最多 100 个排队 job；满载返回明确错误且不遗留孤儿任务。单机文件锁保证调度器唯一；不声称支持分布式 worker。
- 并发上限覆盖 inline 与 queued 混合请求，不允许 inline 绕过池；等待审批不占执行槽。直接 Python SDK/测试调用不经过服务调度，其并发不计入服务承诺，但仍服从任务独占锁，重启扫描不得抢占其持锁任务。
- 调度器启动扫描未完成任务；取得任务独占锁后才能恢复。旧执行者仍持锁时不可抢跑；批准等待任务只等待用户，不能自动批准。多次通知只产生一个可执行 job。
- 调度状态/取消标记独立于整块 checkpoint JSON；checkpoint 更新用 revision CAS，防止工作者覆盖刚写入的取消指令。
- 同步工具在受监督子进程执行，默认单次 5 秒上限、终止与回收宽限 1 秒；deadline 取工具上限与任务剩余预算较小者。SQLite 连接在子进程内创建，不跨进程共享连接。网络模型使用客户端超时和可取消 await。
- 超时先确保旧执行进程终止，再按动作回执判断：有回执则记录真实提交；本地事务已回滚可在同一 action 下有限重试；无法判明则 reconciliation_required，不换 action 盲发。真实平台未来需要适配器级对账，不能继承本地事务假设。
- cancel 排队/待批任务可直接终止；执行中设置持久化标志并停止后续步骤，当前写操作必须先终止执行者并对账。已提交的写入不会因取消自动回滚。
- SIGTERM 停止接单和领取，最多等待 10 秒后终止并回收子进程；恢复时先处理 pending/receipt，不重跑已提交动作。旧进程未确认退出前不得启动同任务替代执行。
- 排队和人工等待不消耗执行 max_seconds；调用、工具执行和退避消耗预算。丢失执行区间按派发时间保守计费，记录预算不确定性。

验收：8 个任务入队，实际执行并发<=2；状态/取消接口在阻塞工具运行时仍可响应。sleep(200) 工具按 5 秒超时、1 秒回收宽限返回；不能要求“5 秒超时又严格 5 秒内完成清理”。提交前后 kill、取消、重启均无重复提交、无丢单、无假成功。

## 后置或不采用

- S5 框架对照单列可选实验，复用相同工具、oracle、用例和故障，比较维护与恢复行为；不把新增 framework 实现塞入主线修复。
- 暂不加 plan 节点、跨任务记忆、工具检索、多 agent、向量库、前端、分布式队列或生产身份系统。没有证据支持按工具数量阈值强制引入这些功能。
- 旧代码先说明归属、分依赖和导入边界，不大规模搬迁或删除；不重写历史提交，不为了“作品感”伪造开发过程。
- 不以零 warning 或减少文件数替代正确性验收；修涉及文件的格式，旧架构告警单列。

## 执行与成本

顺序：第一批→第二批→第三批→第四批→第五批；第五批依赖第二、三批。第一批可独立交付。第五批涉及状态和进程竞争，复杂度最高，不能估成“一行 wait_for”。不承诺未经实现验证的四周工期。

默认单会话执行、分批提交，仅必要时做独立审阅；先跑定向回归，批次末跑对应完整套件。远程模型仅末期显式小批验收；固定用例与种子减少无效重测。原工作区已有大量未提交改造，不混入无关改动；发布副本继续采用脱敏同步，禁止推送原私有历史和凭证。

技术依据：[Python asyncio 超时与线程调用](https://docs.python.org/3.10/library/asyncio-task.html#asyncio.wait_for)、[正在运行的 Future 不能靠 cancel 终止](https://docs.python.org/3.10/library/concurrent.futures.html#concurrent.futures.Future.cancel)。
