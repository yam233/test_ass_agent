# 现有能力可用性修复验收

范围：修复结果证据、缺参续跑、错误分类、调度巡检和并发响应；保留现有单 Agent / 串行工具 / SQLite / 有状态 mock。没有扩展工具、引入图框架或接入真实业务平台。

## 已验证的行为

- 仅有查询证据时不能宣称发放成功；实际数量从平台回执读取，模型编造的完成话术不进入最终结果。
- 缺数量可跨 Runtime 重建后补充，依然先审批再写入；非法补充、篡改已有参数、缺写身份/环境均无副作用。
- 队列入口与 SDK 使用相同澄清规则。持锁期间审批返回409且保持待批；释放锁后重试，实际只写一次。
- 终态任务不参与孤儿恢复，未过期审批不被巡检锁定；排队满/锁冲突不会永久漏掉旧任务。

## 真实模型小样本

模型 `deepseek-v4.1-flash`；五类操作加缺数量续跑，共6/6通过。使用临时 SQLite mock，审批只接受用例指定的工具和精确参数；判分读取实际数据与回执。清理用例预先创建一个合成批次，其两张回执分别来自准备和清理。

模型接口报告共40,612 tokens，低于显式设置的80,000上限。只运行这一轮付费样本，没有扩大评测。报告：[usability-remote.json](../reports/usability-remote.json)。这证明这些用例可用，不是大规模决策准确率，也不证明真实外部平台权限或事务能力。

复现（会调用付费接口）：

```bash
python -m scripts.verify_workflow_usability --config config/local/agent_secrets.json --total-token-budget 80000
```

## 离线验证

完整回归命令为 `python -m pytest tests tests_legacy -q`，包含原有幂等、回执对账、审批、并发、进程关闭/重启、故障注入和新增可用性边界。最终连续运行结果和巡检实测在完成验证后填入本节。

## 边界

- 最终结果仅覆盖已观察操作；明确短语检查不能替代对任意自然语言目标的完整语义判定。
- 结构化缺参的多字段补充需 JSON；普通模型追问仍支持自然语言回复。
- 当前不提供真实外部平台的端到端事务保证；所有写入验收均为有状态 mock。
- 不增加 LangGraph 对照、通用环境接口或多智能体等扩展。
